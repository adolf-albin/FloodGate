📊 Task 3 — Traffic Analysis

Learning Objectives

Now move from discovery to quantitative analysis. Run the controlled simulator and examine how the application's responses change as requests accumulate.

🧪 Lab Steps

  1. Run: python traffic_sim.py
  2. Observe the HTTP responses printed by the simulator.
  3. Inspect /stats after the simulation.
  4. Compare successful responses with rejected responses.
  5. Use the numbers to calculate the traffic pattern.

🧪 Commands

python traffic_sim.py
curl http://127.0.0.1:5000/stats

⚠️ Controlled Lab

All testing must remain against the local FloodGate training service at 127.0.0.1. Do not modify the simulator to target external systems.

Questions

Question 1

During the standard 20-request simulation, how many requests are accepted?

Question 2

During the standard 20-request simulation, how many requests are rejected?

Question 3

What percentage of the 20 simulated requests were accepted?

Question 4

What percentage of the 20 simulated requests were rejected?

Question 5

Which request number is the first one expected to be rejected?

Question 6

What HTTP response pattern shows the transition from accepted traffic to rate-limited traffic?

🧠 Think Like a Defender

Use arithmetic and observed responses together. Traffic analysis is more useful when you can quantify what happened.
